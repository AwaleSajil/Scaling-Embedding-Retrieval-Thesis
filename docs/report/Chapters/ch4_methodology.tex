\section{Experimental Design}
\label{sec:exp_design}

The central design principle of this thesis is controlled comparison: every
compression method, whether post-hoc or training-time, is applied to
the same set of backbone models fine-tuned under identical conditions, and
evaluated on the same benchmark under the same pipeline. This eliminates the
confounds that make cross-method comparisons unreliable in prior work
(Section~\ref{sec:related}).

The experimental workflow has two parallel tracks, both rooted in the same
pre-trained backbone weights. In the post-hoc track, each backbone is
fine-tuned without any compression modification, producing a float32
checkpoint; compression is then applied to the saved embeddings without
touching model weights. In the training-time track, each backbone is
fine-tuned independently from the same pre-trained weights with a modified
architecture or loss function; no float32 checkpoint is used as
initialization. All resulting embedding variants are evaluated on the
NanoBEIR benchmark under the unified pipeline described in
Section~\ref{sec:eval_framework}.

\section{Training Infrastructure and Hyperparameters}
\label{sec:training_infra}

\subsection{Backbone Models}

All training variants are run independently on three backbone architectures:
BGE-base-en-v1.5, RoBERTa-base, and MPNet-base (described in
Section~\ref{sec:biencoder}). No weights are shared across backbones.

\subsection{Training Setup}

Training is implemented with the \textit{sentence-transformers}
library~\cite{reimers2019sbert} using the HuggingFace Trainer API. Multi-GPU
training is performed via PyTorch Distributed Data Parallel (DDP) launched
with \texttt{torchrun} across four GPUs. Gradients are synchronized across
all ranks; checkpoint saving and mid-training evaluation are performed only on
rank~0.

All models are trained in \texttt{bfloat16} precision where hardware support
is available, falling back to \texttt{float16} otherwise. The
\texttt{NO\_DUPLICATES} batch sampler is used within each dataset to prevent
the same (query, document) pair from appearing more than once per batch,
preserving the diversity of in-batch negatives required by the MNRL objective.

\section{Baseline Fine-Tuning}
\label{sec:baseline}

The float32 baseline is produced by fine-tuning each backbone as a standard
\texttt{SentenceTransformer} with mean pooling (Section~\ref{sec:biencoder}).
No compression layer is added. The training objective is the Multiple
Negatives Ranking Loss (MNRL, Section~\ref{sec:contrastive}) computed with
cosine similarity; in-batch negatives are drawn from all other positive
passages in the same batch. Training applies MNRL to batches drawn from all
datasets; the \texttt{WeightedBatchSampler} controls how frequently each
dataset contributes batches during an epoch (Chapter~3).

At the end of training the complete \texttt{SentenceTransformer} checkpoint
(transformer weights, pooling configuration, and tokenizer) is saved to
disk. This checkpoint serves as the common starting point for all post-hoc
compression methods. Training-time compression experiments do not use this
checkpoint; they are fine-tuned independently from the same pre-trained
backbone weights.


\section{Training-Time Compression Experiments}
\label{sec:training_time}

Each training-time experiment fine-tunes the pre-trained backbone directly,
not the float32 baseline checkpoint, modifying either the model
architecture, the loss function, or both. All other settings, including
training infrastructure, hyperparameters, and training data, remain identical to
the baseline.

\subsection{STE Binarization-Aware Training}
\label{sec:bat_ste}

A \texttt{BinarizationLayer} is appended as an additional module after the
mean-pooling layer in the \texttt{SentenceTransformer} module sequence. In
the forward pass the layer applies \texttt{sign($\cdot$)} to the pooled
float32 embedding, mapping each dimension to $\{-1, +1\}$. In the backward
pass the layer acts as the identity (the Straight-Through Estimator,
Section~\ref{sec:compression_bg}), passing gradients to the encoder
unchanged. The loss function is unchanged from the baseline: MNRL with cosine
similarity. Training encourages the encoder to produce pre-binarization
activations already close to $\pm 1$, so that the discrete sign step
introduces minimal information loss at inference time.

At inference, \texttt{sign($\cdot$)} is applied and the resulting bit-vector
is packed into \texttt{uint8} for storage.

\subsection{MRL Fine-Tuning}
\label{sec:mrl_train}

No architectural change is made; the model is identical to the baseline. The
MNRL loss is wrapped by \texttt{MatryoshkaLoss}, which
evaluates them at each of six nested granularities $\{32, 64, 128, 256, 512,
768\}$. The five truncation granularities $\{32, 64, 128, 256, 512\}$ are the
supported post-hoc truncation points; the full-dimension loss ($d = 768$) is
included to ensure the complete representation is not degraded during
training. All six losses are weighted equally ($c_m = 1$ for all $m$,
Equation~\ref{eq:mrl}).

At inference the MRL checkpoint is identical to the baseline float32
checkpoint; truncation to any supported granularity is applied post-hoc by
the evaluation pipeline (Section~\ref{sec:cross_axis}).

\subsection{Joint MRL and STE Binarization-Aware Training}
\label{sec:mrl_bat}

This variant combines the architectural change of
Section~\ref{sec:bat_ste} with the loss modification of
Section~\ref{sec:mrl_train}. The \texttt{BinarizationLayer} (STE) is
inserted after mean pooling, and the loss is \texttt{MatryoshkaLoss} wrapping
MNRL at all six granularities. The combination trains representations that are
both nested and binarization-aware, enabling post-hoc truncation followed by
binary packing.

\subsection{Annealed Tanh Binarization-Aware Training}
\label{sec:bat_atanh}

An \texttt{AnnealedTanhBinarizationLayer} replaces the STE layer after mean
pooling, applying the annealed tanh surrogate described in
Section~\ref{sec:compression_bg}. The annealing rate is $\gamma = 0.1$,
following \cite{yamada2021efficient}; the empirical validation of this choice
across $\gamma \in \{0.05, 0.1, 0.2\}$ is reported in
Table~\ref{tab:gamma_ablation}. At approximately $t = 8{,}000$ steps (one
epoch over the full training mixture), $\beta \approx 28$, at which point
$\tanh(\beta_t \cdot \mathbf{e}) \approx \text{sign}(\mathbf{e})$ for typical
activation magnitudes.

A \texttt{BetaAnnealCallback} increments $t$ after every optimizer step and
logs $\beta$ to Weights \& Biases. At inference the layer switches to the
hard \texttt{sign($\cdot$)} function. The loss function is MNRL with cosine
similarity applied to the soft-binarized embeddings during training.

\subsection{Joint MRL and Annealed Tanh Binarization-Aware Training}
\label{sec:mrl_atanh}

This variant combines the \texttt{AnnealedTanhBinarizationLayer} of
Section~\ref{sec:bat_atanh} with the \texttt{MatryoshkaLoss} of
Section~\ref{sec:mrl_train}. Architecture and loss are modified
simultaneously, training representations that are both nested and
binarization-aware via the smooth annealed surrogate.


\section{Post-Hoc Compression}
\label{sec:posthoc}

All post-hoc methods are applied after the float32 checkpoint has been
trained; they do not modify the model weights. Raw float32 embeddings are
encoded once and cached (Section~\ref{sec:eval_framework}); the compression
transform is applied at evaluation load time.

\subsection{INT8 Scalar Quantization}

Following the procedure in Section~\ref{sec:compression_bg} (Equation~\ref{eq:int8}),
calibration bounds are derived from the first 1,000 corpus embeddings after any
dimensionality truncation. The same bounds are applied identically to corpus and
query embeddings. Similarity is cosine similarity on the quantized representations.

\subsection{Binary Quantization}

Post-hoc binary quantization follows the procedure in
Section~\ref{sec:compression_bg}. Bits are packed into \texttt{uint8} format
using the \textit{sentence-transformers} \texttt{quantize\_embeddings} utility.
Similarity is Hamming similarity between packed binary query and corpus vectors.

\subsection{Product Quantization}

PQ is fitted on corpus embeddings using Faiss~\cite{douze2024faiss} following
the procedure in Section~\ref{sec:compression_bg}. $M \in \{16, 24, 32, 48, 64, 96, 128, 192\}$ sub-spaces are evaluated with
centroid bit-widths of $n_{\text{bits}} \in \{4, 8\}$.

\subsection{TurboQuant}

TurboQuant~\cite{zandieh2025turboquant} is calibrated on the corpus embeddings
via the \texttt{TurboQuantMSE} fitter (Section~\ref{sec:compression_bg}).
Bit-depths of $\{1, 2, 3, 4, 8\}$ bits per dimension are evaluated.


\section{Stacked Combinations}
\label{sec:cross_axis}

MRL-trained checkpoints support simultaneous compression along two dimensions:
dimensionality reduction via post-hoc truncation, followed by any
precision-reducing method. Specifically, each MRL checkpoint is truncated to
each of the five supported granularities $\{32, 64, 128, 256, 512\}$, and
then binary quantization, PQ, or TurboQuant is applied to the truncated
embedding. This yields a grid of (backbone $\times$ truncation dimension
$\times$ precision method) combinations evaluated in Chapter~5.

Each combination is registered as a separate \texttt{ModelSpec} in
\texttt{eval\_v2/config/models.py}. All variants that share the same
checkpoint reuse a single cached float32 embedding, so encoding is performed
only once per checkpoint regardless of how many compression variants are
derived from it.


\section{Evaluation Framework}
\label{sec:eval_framework}

\subsection{Embedding Cache and Transform Pipeline}

Raw float32 embeddings are computed once per checkpoint and stored under a
content-addressed cache. The cache key is the first 16 hex characters of the
SHA-256 hash of the model path, ensuring distinct checkpoints produce distinct
cache entries while variants sharing a checkpoint reuse a single cached copy.
For each NanoBEIR subset, corpus and query embeddings are stored as compressed
NumPy arrays (\texttt{.npz}) together with a JSON sidecar recording the model
path, embedding count, and dimension. A cache miss triggers a multi-GPU
encoding pass.

At evaluation time, the transform pipeline is applied to the cached float32
embeddings in the following fixed order:
%
\begin{enumerate}
  \item Dimensionality truncation (if \texttt{truncate\_dim} is set).
  \item Binary quantization and \texttt{uint8} packing (if
        \texttt{similarity = hamming}).
  \item INT8 scalar quantization (if \texttt{quant\_bits} $= 8$).
  \item PQ fitting and asymmetric reconstruction (if \texttt{pq\_M} is
        set); fitted on corpus.
  \item TurboQuant quantization and dequantization (if \texttt{tq\_bits}
        is set); fitted on corpus.
\end{enumerate}
%
Steps 4 and 5 are mutually exclusive; only one precision-reducing transform
is active per model variant.

\subsection{Metrics}
\label{sec:metrics}

The four retrieval metrics used in this thesis, NDCG@$k$, MRR@$k$,
Accuracy@$k$, and Recall@$k$, are defined in Section~\ref{sec:ir_eval}.
All are computed at $k \in \{1, 3, 5, 10\}$, averaged over the 50 queries
per NanoBEIR subset, then macro-averaged across the 13 subsets.
MRR is the primary reported metric throughout Chapter~5.

\subsection{Memory Budget and Compression Ratio}
\label{sec:memory}

Embedding memory is computed as:
%
\begin{equation}
  \text{memory (bytes)} = n \times d_{\text{stored}} \times \frac{b}{8},
  \label{eq:memory}
\end{equation}
%
where $n$ is the number of embeddings, $d_{\text{stored}}$ is the stored
dimension (number of PQ sub-spaces for PQ variants), and $b$ is the number
of bits per stored element. For float32, $b = 32$; for INT8, $b = 8$; for
binary packed embeddings, $b = 1$. Compression ratio is
reported relative to the float32 baseline at the same embedding dimension.

\subsection{Statistical Significance Testing}
\label{sec:significance}

The tests used here are defined in Section~\ref{sec:significance_bg}. For each
model pair, per-query scores are collected across all 13 NanoBEIR subsets
and pooled into a single paired sample (649 query pairs per comparison). The
per-query difference is $d_i = s_A(q_i) - s_B(q_i)$ for each query $q_i$,
where $s(\cdot)$ denotes the retrieval score of the respective model. The Shapiro--Wilk test is first applied to this vector of differences to
assess normality. If normality is not rejected, the paired $t$-test is used;
otherwise the Wilcoxon signed-rank test is used. Cohen's $d$ is reported as
an effect size in either case. Results in Chapter~5 are flagged as
statistically significant at $\alpha = 0.05$.
